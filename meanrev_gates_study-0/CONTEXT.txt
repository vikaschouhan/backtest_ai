================================================================================
MEAN-REVERSION REGIME GATE STUDY - CONTEXT RESUME (v2, 2026-10-17)
================================================================================

[SUMMARY]
A causal regime gate (state machine with hysteresis) that tells a mean-reversion
strategy, per closed bar, whether it may open trades and whether it must go flat.
Tested on synthetic OU / random-walk / trend / regime-switch prices.
Repo: github.com/vikaschouhan/backtest_ai, directory meanrev_gates_study-0/.
Code lives in the .py files; this file holds the spec, history and findings.
Context: complements the user's mean-reversion framework (ADF, Hurst, OU, GARCH,
z-scores, ADX regime layer) and strategy-search engine (Python orchestration +
C hot-path kernel). Target markets: Nifty, BankNifty, MCX.

--------------------------------------------------------------------------------
PART 1: CURRENT SPEC
--------------------------------------------------------------------------------
- Call RegimeGate.on_bar(Features) once per CLOSED bar, in order. No lookahead:
  features must come from rolling windows ending at that bar.
- Features: hurst, adf_pvalue, half_life (bars), adx, blackout (bool).
  None = unavailable -> that check FAILS (no data, no trade).
- Output GateDecision: regime, allow_entries, force_exit, score, reasons[].
- The gate does NOT generate trades; signal + exits live in the strategy.

CHECKS (score = fraction passing, 6 checks)
  hurst            hurst < 0.45
  adf              adf_pvalue < 0.05
  adx              adx < 20
  half_life_range  2 <= half_life <= 30
  half_life_stable std/mean of last <=20 half-lives < 0.35 (needs >=5 values)
  adf_falling      mean(last 10 p) <= mean(previous 10 p), or last-10 mean < 0.01

STATES
  TRENDING        no entries; positions flat
  TRANSITIONAL    no new entries; open positions run to their own exits
  MEAN_REVERTING  entries allowed
  Start state: TRENDING.

TRANSITIONS (evaluated in this order each bar)
  1. Hard break: hurst > 0.58 OR adx > 30  -> TRENDING, force_exit, cooldown=10,
     reset confirmation counters. No confirmation needed.
  2. In MR: score < 0.55 for 2 consecutive bars -> TRANSITIONAL.
  3. In TRENDING/TRANSITIONAL:
       score >= 0.80 for 3 consecutive bars (and cooldown == 0) -> MR
       TRANSITIONAL and score < 0.30 -> TRENDING, force_exit
       TRENDING and score >= 0.55 (and cooldown == 0) -> TRANSITIONAL
  Blackout: allow_entries = False in any state; if blackout_forces_exit, also
  force_exit. State itself is unchanged.
  All thresholds live in GateConfig.

V2/V3 OPTIONS (GateConfig; defaults reproduce v1 exactly)
  use_adf_falling  True  -> False drops the adf_falling check (5 checks)
  require_core     False -> True: mandatory "core" test each bar:
                   core = adf_pvalue < adf_p_max OR hurst < core_hurst_max (0.40)
                   core fails -> score = min(score, core_fail_cap=0.50), reason
                   "core_fail". 0.50 < exit 0.55 (blocks entry / leaves MR after
                   confirm_out) and > trend 0.30 (no forced flat on its own).
  v2_config()  = use_adf_falling=False, require_core=True
  v3_config()  = v2 + core_hurst_max=-inf (core = ADF alone)
  ADF window is a feature-side choice: v2/v3 are meant to get ADF on 250 bars
  (other features stay on 120).

PERSISTENCE
  to_json() / from_json() save config, state, counters, cooldown and the
  half-life / ADF histories, so a restart continues identically (tested).

REFERENCE FEATURES (regime_gate.py, for testing / parity with C kernel)
  hurst_exponent  slope of log std(lagged diffs) vs log lag, lags 2..19
  ou_half_life    AR(1): dx = a + b*x[t-1]; HL = -ln2 / ln(1+b); inf if b>=0
  adf_pvalue      statsmodels adfuller(maxlag=1, autolag=None); None if missing
  adx             Wilder ADX(14) from high/low/close

--------------------------------------------------------------------------------
PART 2: TEST SETUP (gate_tests.py)
--------------------------------------------------------------------------------
- 1,500 bars per run, 120-bar feature window, 10 seeds (1000..1009).
- Scenarios: ou_strong (theta 0.10, sigma 0.6), ou_weak (theta 0.02),
  random_walk (sigma 0.6), trend (drift 0.12), regime_switch (4 equal segments:
  OU -> trend(drift 0.20) -> OU -> random walk). High/low = close +/- |N(0,0.3)|.
- Toy strategy: 20-bar z-score; long z < -2, short z > 2; exit at z crossing 0,
  20-bar time stop, or gate force_exit; cost 0.02 pts per side; fills at bar
  close (toy, not realistic). Gated version only enters when allow_entries.
- Figures: seed 0 per scenario (price shaded by gate state, score with
  thresholds, cumulative PnL gated vs ungated) + summary over all seeds.

--------------------------------------------------------------------------------
PART 4: FINDINGS
--------------------------------------------------------------------------------
- Main job works: trend loss cut from -74 to -7; regime switch flips to profit.
- Strong OU gives up ~17% of ungated PnL (warm-up + short TRANSITIONAL dips).
- Too permissive on random walks (MR 28% of bars):
    * adf_falling is a coin flip on every process -> pure noise in the score.
    * ADF is the sharpest discriminator (2% pass on RW) but only 1 vote of 6;
      5/6 >= 0.80 lets the gate open with ADF failing.
    * AR(1) half-life on a 120-bar random walk is biased toward reversion, so
      half_life_range passes 64% of the time.
- Re-entry lag (~60 bars) is driven by the 120-bar window still holding the
  previous regime.
- Weak OU (half-life 34) mostly rejected - correct, it's outside the 30-bar cap.
- numpy gotcha: comparing arrays of str-Enum members (np.array(...) == Regime.X)
  silently returns all False; use identity checks per element.

PART 5: FIX ATTEMPT - ABLATION (gate_ablation.py, results/v2/)
--------------------------------------------------------------------------------
Same 10 seeds; features computed once per seed (ADF on 120 and 250 bars) and
shared by all variants. Metrics from bar 120 for every variant (ADF250 has no
value before bar 250 -> counted as a cost).

  variant                 OUs MR%  RW MR%  TR MR%  TR PnL  RS PnL  prec/rec  lag out/in
  v1                        85.5    27.8     6.3    -6.6   +19.8    72/69     16/60
  drop adf_falling          94.7    36.5    10.0    -9.3   +23.0    70/79     36/56
  + core (adf120|H<.40)     82.8    23.1     7.1    -7.0   +18.4    73/68     22/56
  + adf250 = v2              94.1    24.1     7.0    -5.9   +23.2    74/78     58/63
  drop adf_falling+adf250   96.8    37.2    10.5    -8.8   +24.8    71/84     58/61
  v3 (core = adf250 only)   83.6     3.6     0.5    -0.2   +14.8    82/51     22/97
  (OUs = strong OU, RW = random walk, TR = trend, RS = regime switch;
   ungated PnL: OUs +64.3, OU weak +18.3, RW -5.9, TR -73.9, RS -4.6;
   OU weak MR%: v1 40.5, v2 36.3, v3 11.5. Gated PnL sd ~6-13 pts.)

Diagnostics (3 seeds, windows every 5 bars from bar 250):
  process      hurst120 median  P(H<.40)  P(adf120<.05)  P(adf250<.05)  P(v2 core)
  random_walk       0.45           32%         2%             4%           35%
  ou_strong         0.30           87%        39%            95%           99%
  trend             0.45           32%         3%             1%           33%

Findings:
- Dropping adf_falling alone is WORSE: 0.80 entry = 4/5 instead of 5/6.
- v2 barely helps: its core passes via Hurst, and 120-bar Hurst is biased low
  (0.45 median on a pure random walk).
- ADF on 250 bars is the sharp discriminator (95% vs 4% vs 1%).
- v3 removes false positives (RW 3.6%, trend 0.5%, trend loss ~0, precision
  82%) while strong OU stays at v1's level. Cost: recall 51%, re-entry lag ~97
  bars, weak OU mostly rejected. ~130 bars of recall loss is backtest warm-up.
- Recommendation: v3 as the safe default where false "on" is costly; v1/v2
  where missed MR stretches cost more.

--------------------------------------------------------------------------------
PART 6: OPEN ITEMS / NEXT STEPS
--------------------------------------------------------------------------------
1. Speed v3 re-entry without reopening false positives: ADF250 for entry only,
   faster 120-bar checks + hard break for exit; or try a ~180-bar ADF.
2. Replace/bias-correct the 120-bar Hurst, lengthen its window, or drop it.
3. Realistic costs and >= 50 seeds so PnL gaps are resolvable.
4. Ideas raised for TRANSITIONAL: tighter risk (break-even stop / shorter time
   stop), block scaling-in, max dwell (~20 bars) then TRENDING.
5. Calibrate on real Nifty/BankNifty/MCX data: label bars by forward strategy
   profitability; search enter_score, confirm_in, window length via the
   strategy-search engine, scored on gated PnL net of costs.
6. Live deployment checklist (discussed): closed-bar features only, event
   blackouts (RBI, Budget, CPI, expiry, VIX spikes), persisted state +
   broker reconciliation, kill switch, vol-scaled sizing, broker's SEBI
   retail-algo requirements, monitor realized half-life and slippage drift.
